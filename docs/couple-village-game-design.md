# 커플 마을 지키기 — 게임 설계서 (v0.1)

> 기준 파일: `ceeec44d-index.html` (Three.js r128 + 2.5D 폴백, 단일 HTML)
> 목표: 안드로이드·아이폰 모두에서 온라인 커플 마을 건설 + 외부 몬스터로부터 집 지키기
> 그래픽: 현재 파일과 같은 3D 느낌을 유지하되 더 귀엽게 (무료 에셋 활용)

---

## 1. 현재 파일 진단 (먼저 짚어둘 문제)

| 항목 | 현재 상태 | 영향 / 조치 |
|---|---|---|
| 온라인 동기화 | `BroadcastChannel` 사용 | **같은 브라우저·같은 기기 탭끼리만 동기화됨.** 다른 기기(아이폰↔안드로이드)는 연결 안 됨. 실서버(Supabase Realtime 등) 필요 |
| API 키 | Gemini 키를 클라이언트 `localStorage`에 저장 | 배포 시 키 노출. TTS 호출은 서버(Edge Function)로 옮기고 키는 서버 환경변수로 |
| 3D 모델 | 원기둥·구·콘으로 만든 임시 캐릭터·건물 | 귀여움이 부족함. GLB 무료 모델로 교체 |
| 건물 동기화 | 변경마다 전체 맵(JSON)을 전송 | 건설 1회 = 이벤트 1개(RPC)로 바꿔야 충돌·용량 문제 해결 |
| 스프라이트 | 업로드한 PNG를 로컬에만 적용 | 몬스터 에셋은 프로젝트 자산으로 포함(빌드 시 번들)해야 모든 기기에서 보임 |
| 라이브러리 | Three r128을 unpkg에서 로드 | npm + Vite로 번들링. 버전 고정·오프라인 캐시 |
| 저장 | `localStorage`만 사용 | 계정·서버 저장 필요 (기기 바꾸면 마을이 사라짐) |

**결론:** 지금 코드는 "3D 느낌 프로토타입"으로는 훌륭하지만, 온라인 커플 게임의 뼈대(서버·계정·동기화)는 새로 짜야 합니다. 3D 렌더링 로직(카메라 추적, 조이스틱, 배틀 패널)은 재사용 가능합니다.

## 2. 컨셉

- **한 줄 소개:** 둘이서 꾸미는 파스텔 마을, 밤마다 찾아오는 몬스터로부터 우리 집을 지키는 협동 디펜스.
- **플랫폼:** 모바일 웹(PWA) 우선. 아이폰·안드로이드 모두 브라우저에서 바로 실행, 홈 화면에 추가하면 앱처럼 동작.
- **플레이 인원:** 커플 2인 (온라인). 선택 확장으로 친구 4인 마을.
- **톤:** 밝고 따뜻함. 몬스터도 무섭기보다 말썽꾸러기 느낌.

## 3. 핵심 루프

```
낮: 마을 꾸미기 · 자원 모으기 · 탐험(풀숲)
  ↓
저녁: 마을 방어 준비 (울타리·타워·함정 배치)
  ↓
밤: 습격 웨이브 (몬스터가 집을 향해 이동 → 방어)
  ↓
아침: 결과 보고서 (막은 몬스터 수, 손상된 건물, 획득 보상)
  ↓
마을 레벨업 → 새 건물 해금 → 더 강한 밤
```

- 낮/밤은 실시간 약 10분 사이클 (실제 시간 기준 서버에서 계산 → 두 사람의 화면이 항상 같은 시간대).
- 한 사람이 접속하지 않아도 습격은 진행되고, 다음 접속 때 보고서가 뜸 (오프라인 보상과 동일 구조).

## 4. 커플 시스템

1. **방 만들기 / 참여**
   - 한 명이 "우리 마을 만들기" → 8자리 랜덤 초대 코드 발급 (예: `K7F2-QM9X`) → 카카오톡 등으로 공유.
   - 상대는 코드 입력 또는 링크로 입장. 방 최대 2인 (확장 시 4인).
   - 기존 `VILLAGE-1004` 같은 고정 코드는 추측 가능하므로 사용 금지.

2. **역할 분담 (재미 요소)**
   - 캐릭터 2명: 한 명은 **건축가**(건물 설치 비용 할인), 한 명은 **수호자**(전투 공격력 보너스).
   - 역할은 선택 가능, 언제든 변경 가능.

3. **공동 자원**
   - 마을 공용 자원 `별 조각`: 탐험·습격 성공 시 획득. 건설·회복에 사용.

4. **하트 콤보**
   - 두 캐릭터가 가까이 붙어 있으면 하트 게이지가 차고, 가득 차면 **공동 스킬** (예: 범위 빛 폭발) 사용 가능.
   - 상대 캐릭터 위치는 말풍선 없이 하트 이펙트로만 표시 (상호 협동 유도).

5. **편지 / 기념일**
   - 비동기 기능: 상대가 접속하지 않았을 때 "오늘 밤 조심해!" 같은 짧은 메시지(이모지·스티커 중심, 자유 텍스트는 길이 제한) 남기기.
   - 기념일(사귄 날, 결혼 기념일 등)에 마을에 특별 건물·장식 자동 해금. 날짜는 사용자가 직접 입력.

6. **채팅 정책**
   - 자유 채팅은 1차 출시에서 제외 (운영·신고·욕설 필터 부담이 큼). 이모지 리액션 + 스티커 + 짧은 편지로 대체.

## 5. 방어 시스템

### 5-1. 습격 웨이브
- 밤마다 웨이브 1~N. 웨이브 수가 늘수록 몬스터 수·종류 증가.
- 몬스터는 **마을 경계 밖에서 생성 → 가장 가까운 집/건물을 향해 이동** → 울타리·건물에 막히면 부수며 진입.
- 집 HP가 0이 되면 해당 건물 "손상" 상태 → 수리 비용 필요 (파괴가 아닌 손상으로 처리해 좌절감 완화).

### 5-2. 방어 건물 (기존 4종 확장)

| 건물 | 기존 | 역할 | 신규 |
|---|---|---|---|
| 아담한 집 | ✅ | 보호 대상, HP 보유 | 집 레벨 (수리·업그레이드) |
| 나무 울타리 | ✅ | 몬스터 이동 차단, 짧은 시간 막음 | 울타리 HP |
| 꽃밭 화단 | ✅ | 주변 건물 회복 (치유 오라) | 꽃 종류별 효과 |
| 가로등 | ✅ | 밤에 빛 반경, 몬스터 약화 | 라이트 타워(사거리 공격) |
| 함정 | ❌ | 밟은 몬스터 감속·피해 | 신규 (가시 덫, 반짝 덫) |
| 종 탑 | ❌ | 웨이브 알림 + 전체 몬스터 어그로 분산 | 신규 (해금 레벨 3) |

### 5-3. 전투 방식 (하이브리드)
- **자동 방어:** 건물(타워·덫)이 자동 공격.
- **직접 전투:** 캐릭터를 조이스틱으로 움직여 몬스터를 직접 때림 (기존 `useSkill` 로직 재활용: 스파크 빔 / 전광 돌진 / 회복).
- 기존의 "풀숲 랜덤 배틀(턴제 패널)"은 **낮 탐험 전용 미니 배틀**로 유지. 밤 습격은 실시간 액션으로 분리.

## 7. 그래픽 설계 (현재 3D 느낌 유지 + 귀엽게)

### 7-1. 스타일 원칙
- **Toon 셰이딩**: `MeshLambertMaterial` → `MeshToonMaterial`로 교체, 단계형 음영으로 귀여운 느낌.
- **외곽선(아웃라인)**: 인버티드 헐(뒷면을 살짝 키워 검은/진한 색으로) 방식. 셰이더 없이 가능하고 모바일에 가벼움.
- **작은 머리·큰 눈**: 캐릭터 비율을 chibi 체형으로 (머리:몸 = 1:1).
- **팔레트 유지**: 기존 파스텔 (잔디 `#9ccc65`, 광장 `#fff3e0`, 하늘 `#89f7fe` → `#66a6ff`, 지붕 `#ff7043`, 벽 `#fff8e1`).

### 7-2. 카메라 & 조명
- 카메라: 현재와 같은 **45° 탑다운 추적 카메라** 유지 (`PerspectiveCamera(45)`, 플레이어 뒤쪽 위).
- 낮: `HemisphereLight` + 방향광 1개(그림자 1개만, 모바일 그림자 맵 512~1024).
- 밤: 하늘색 → 남보라 틴트 전환, 가로등·라이트 타워 `PointLight` 대신 **발광 스프라이트(글로우)** 사용 (모바일 라이트 수 제한).
- 낮/밤 전환은 `scene.background`와 `fog`, 조명 강도를 lerp.

### 7-3. 성능 가이드 (모바일 기준)
- 목표: 최신 아이폰·갤럭시 **60fps**, 중급 안드로이드 **30fps 이상 보장**.
- Draw call 150 이하: 풀숲·나무는 **`InstancedMesh`** 로 묶기 (기존 `grassMeshes`는 개별 Mesh → 인스턴스화).
- 텍스처: 2048 아틀라스 1장으로 건물·캐릭터 머티리얼 통합.
- 픽셀 비율 상한 `min(devicePixelRatio, 2)` 유지 (기존 코드 적용됨).
- 그림자는 캐릭터 아래 **블롭 그림자(원형 텍스처)** 를 기본으로, 실시간 그림자는 옵션.
- 파티클 최소화: 꽃잎·반딧불 정도 (풀 파티클 시스템 금지).

### 7-4. 무료 에셋 소스 (상업 이용 가능 여부는 다운로드 시 라이선스 확인)

| 소스 | 내용 | 용도 | 라이선스 메모 |
|---|---|---|---|
| **Kenney.nl** | Nature Kit, Tiny Town, Furniture Kit 등 | 나무·집·울타리·가로등 GLB | CC0 (공개 도메인 수준) |
| **Quaternius** | Ultimate Monsters, Nature/Town 팩 등 | 몬스터·소품 GLB | CC0 계열 (팩별 확인) |
| **Mixamo** | 캐릭터 리그 + 걷기/공격/춤 애니메이션 | 캐릭터 동작 | 무료 (Adobe 계정 필요), 재배포 제한 확인 |
| **itch.io 무료 팩** | 귀여운 UI, 아이콘, 파티클 텍스처 | UI·이펙트 | 팩마다 상이, 반드시 확인 |
| **기존 Monsters_Creatures_Fantasy** | 몬스터 스프라이트 | 전투·몬스터 | 보유 파일 라이선스 확인 후 번들 |

> 주의: Synty 등 유료 에셋 팩은 설계상 제외. 모든 에셋은 `assets/LICENSES.md`에 출처·라이선스를 기록하는 것을 권장.

## 8. 기술 스택 (크로스플랫폼 전략)

| 영역 | 선택 | 이유 |
|---|---|---|
| 클라이언트 | **Three.js + Vite + TypeScript** (PWA) | 아이폰·안드로이드 동일 코드, 스토어 없이 즉시 배포 |
| 백엔드 | **Supabase** (Auth · Postgres · Realtime · Edge Functions) | 무료 티어로 시작, 이미 연결 가능한 MCP 있음 |
| 실시간 위치 | Supabase **Realtime Broadcast** (10Hz 스로틀, 클라이언트 보간) | 위치는 저장 불필요, 가볍고 빠름 |
| 건설·결과 | **Postgres RPC** (서버에서 비용·충돌 검증 후 저장) | 두 명이 동시에 같은 칸에 짓는 문제 방지 |
| 습격 스케줄 | Edge Function + cron (서버 시간 기준) | 시간 조작·기기별 차이 방지 |
| TTS | Edge Function이 Gemini 호출 (키는 서버 보관) | 키 노출 방지 |
| 호스팅 | Cloudflare Pages 또는 Vercel | HTTPS 기본 제공 (iOS 홈 화면 추가·오디오에 필요) |
| 스토어 배포 (선택) | **Capacitor**로 래핑 | 나중에 App Store / Play 출시 시 코드 재사용 |

### 8-1. 플랫폼별 주의사항
- **iOS Safari:** 오디오는 사용자 터치 후에만 재생 → 첫 탭에서 `AudioContext` 해제. WebGL 메모리 제한 → 텍스처 크기 관리.
- **iOS 홈 화면 앱:** 설치 시 전체 화면. 노치·안전영역 `env(safe-area-inset-*)` 적용 필요.
- **안드로이드 Chrome:** 대체로 문제 없음. 저사양 기기에서 프레임 드롭 대비 자동 품질 낮춤 옵션(그림자 끄기, 풀 밀도 감소).
- **입력:** 기존 `pointer` 이벤트 기반 조이스틱 그대로 사용 가능. 멀티터치(조이스틱 + 버튼 동시) 테스트 필수.
- **`touch-action: none` 전역 적용 금지:** 모달 내부 입력창은 스크롤·입력 허용 영역으로 분리.

## 9. 데이터 모델 (초안)

```
profiles        (id, nickname, created_at)            -- 익명 로그인 기본
villages        (id, invite_code, name, level, stars, night_no, created_at)
village_members (village_id, profile_id, role, heart_gauge)
buildings       (id, village_id, type, x, z, hp, level, placed_by)  -- 칸 단위 유니크 인덱스
raids           (id, village_id, wave, started_at, result_json)
letters         (id, village_id, from_profile, body_code, created_at)
```

- **RLS(행 수준 보안):** 본인이 속한 `village_id`만 읽기·쓰기 가능.
- **건설 RPC:** `place_building(village_id, type, x, z)` → 자원 차감, 칸 중복 검사, 최대 개수 검사를 한 트랜잭션에서.
- 위치 데이터는 DB에 저장하지 않음 (Realtime만).

## 10. 네트워크 흐름

1. 접속: 익명 로그인 → 초대 코드로 `village_id` 조회 → 방 구독(Realtime 채널 `village:{id}`).
2. 이동: 로컬 입력 → 10Hz로 `{id, x, z, rotY}` 브로드캐스트 → 상대는 보간(lerp)으로 부드럽게 표시.
3. 건설: 클라이언트 → RPC 호출 → 성공 시 채널에 `BUILD_ADDED` 이벤트 → 양쪽 화면 반영.
4. 습격: Edge Function이 서버 시간 기준 웨이브 시작 → `RAID_START` 이벤트 + 웨이브 설정값 전달 → 클라이언트는 같은 시드로 몬스터 스폰 (결과 판정은 서버가 최종 확정).
5. 접속 끊김: 재접속 시 `villages` + `buildings` 전체를 한 번 가져와 상태 동기화 (이벤트 누락 대비).

## 13. 개발 환경 (Mac mini 활용)

- Mac mini는 현재 **온라인 상태**로 확인됨 (Apple Silicon, Node 24).
- 역할 제안:
  - Claude Code 상시 작업 환경 (코드 작성·빌드·테스트).

  - 로컬 개발 서버 + Supabase 로컬(Docker)로 백엔드까지 자체 검증.
- **필요 권한:** Claude Code가 프로젝트 파일을 읽고 쓰려면 해당 작업 폴더를 연결해야 합니다 (현재 연결된 폴더 없음). 개발 시작 시 프로젝트 폴더만 허용하면 됩니다.
