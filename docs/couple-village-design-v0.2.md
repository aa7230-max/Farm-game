# 커플 마을 게임 — 설계 v0.2 (변경 사항)

> v0.1(`couple-village-game-design.md`)에서 바뀐 부분만 정리합니다. 바뀌지 않은 내용(3D 렌더링, 방어 루프, 몬스터 AI 등)은 v0.1을 그대로 따릅니다.

---

## 1. 확정 방향

| 항목 | v0.1 | **v0.2 (확정)** |
|---|---|---|
| 배포 | PWA 우선, 스토어 검토 | **웹 전용.** 스토어 출시 없음. 홈 화면에 설치하는 웹앱 |
| 목적 | 출시 가능한 게임 | **개인용 온라인 커플 게임.** 지인 초대 중심, 공개 마케팅 없음 |
| 인원 | 커플 2인 | **최대 4인** (커플 2인 + 친구·가족 확장) |
| 테마 | 몬스터 디펜스 | **테마 선택형**: 몬스터 / 좀비 (엔진은 공통, 콘텐츠만 교체) |
| 게임 내용 | 방어 중심 | **마을 건설·성장 + 여행 + 밤 습격 방어** |
| 감성 | 파스텔 기본 | **파스텔 + 둥근 감성 UI** (말랑한 버튼, 손글씨 폰트, 부드러운 그림자) |
| 개발 관리 | 미정 | **GitHub 저장소로 계속 업데이트** (커밋 = 업데이트 이력) |

> 스토어 없이 웹으로 가면 심사·결제 제약은 없어지지만, **iOS 설치 방식이 제한적**이라는 점은 아래 6장에서 따로 짚겠습니다.

## 2. 여행 시스템 (신규)

마을 밖 지역을 **여행 카드**로 골라 떠나는 구조입니다.

- **지역 6~8곳 시작:** 숲, 바닷가, 눈산, 사막 오아시스, 버섯 동굴, 구름 섬 등.
- **두 가지 여행 방식**

| 방식 | 설명 | 네트워크 부담 | 출시 순서 |
|---|---|---|---|
| **파견 여행** | 한 명이 골라서 떠나면 시간이 지나 결과(재료·기념품·스탬프) 도착 | 낮음 (비동기) | **M3에 먼저** |
| **함께 여행** | 여러 명이 같은 지역 맵에 동시에 들어가 탐험·몬스터 처치 | 높음 (맵 동기화) | M4 |

- **여행 스탬프북:** 방문한 지역마다 일러스트 스탬프가 찍힙니다. 사진 대신 손그림 스탬프로 감성을 살립니다.
- **여행 보상:** 지역별 재료 → 마을의 새 건물 해금 (예: 바닷가 → 등대, 눈산 → 온천).

## 3. 4인 동기화 변경

| 영역 | 설계 |
|---|---|
| 위치 | 최대 4명 × 10Hz 브로드캐스트 → 트래픽 충분히 가벼움 |
| 건설 | 서버 RPC로 칸 충돌 방지 (v0.1 유지) |
| 습격 | 접속자 0명이어도 진행, 다음 접속 때 보고서 |
| 재접속 | 방 전체 상태 스냅샷 1회 → 이벤트 누락 보정 |
| 역할 | 4인이면 역할 4종: **건축가 · 수호자 · 요리사(회복 담당) · 탐험가(여행 보너스)** |
| 하트 콤보 | 2인 조합 → **4인 합동 스킬**로 확장 (4명이 가까이 모이면 발동) |

## 4. 테마 구조 (몬스터 ↔ 좀비 교체)

엔진 코드는 하나, **콘텐츠는 테마 폴더로 분리**합니다.

```
content/themes/
  monster/
    theme.json       # 몬스터 목록, 능력치, 대사, 밤 웨이브 구성
    assets/          # 몬스터 스프라이트·GLB
  zombie/
    theme.json       # 좀비 목록 (말랑 좀비 · 느릿 좀비 · 우산 좀비 등)
    assets/
```

- **좀비 테마 톤:** 무섭기보다 **귀여운 느릿 좀비**. 파스텔 색, 큰 눈, 공격 대신 "간지럼 공격" 같은 가벼운 표현 — 감성 게임 톤을 해치지 않도록.
- 방 생성 시 테마 선택 → 방 안의 모든 사람이 같은 테마를 공유합니다.
- 나중에 테마를 추가하면 코드 변경 없이 폴더만 추가하면 됩니다 (예: 우주 테마, 눈사람 테마).

## 5. GitHub 기반 운영

### 5-1. 저장소 구조

```
village-game/
  src/                  # 게임 코드 (TypeScript + Three.js)
  public/               # 정적 파일, manifest.json, 아이콘
  content/themes/       # 테마 팩 (4장)
  supabase/migrations/  # DB 스키마 SQL (변경 이력 보관)
  docs/                 # 설계서 (v0.1, v0.2 …)
  CHANGELOG.md          # 버전별 변경 기록
  README.md
```

### 5-2. 배포 흐름

- **호스팅: GitHub Pages** — 무료, HTTPS 자동 (아이폰 홈 화면 설치에 HTTPS 필수).
  - 단, **private 저장소에서 Pages를 쓰려면 유료 플랜**이 필요합니다. 저장소를 public으로 두거나, 비공개 유지가 중요하면 **Cloudflare Pages**(private 저장소 지원)를 씁니다.
- **GitHub Actions:** `main`에 푸시 → 자동 빌드 → 자동 배포. 커밋 자체가 업데이트 이력이 됩니다.
- **브랜치:** `main`(배포본) / `dev`(작업) — 혼자 개발해도 실수로 배포본을 깨지 않게 하는 용도.
- **버전 표시:** 앱 하단에 `v0.x.y` 표시, `CHANGELOG.md`와 맞춤.

### 5-3. 비밀 키 관리 (중요)

| 키 | 위치 | 이유 |
|---|---|---|
| Supabase **anon key** | 클라이언트 코드 OK | 공개되어도 RLS로 보호되는 키 |
| Supabase **service role key** | 서버(Edge Function) 환경변수만 | 클라이언트 노출 시 DB 전체 권한 |
| Gemini API 키 | Edge Function 환경변수만 | 클라이언트 노출 금지 |

- GitHub 저장소에는 **어떤 키도 커밋하지 않습니다.** `.env`는 `.gitignore`에 등록.

## 6. 웹 설치 UX와 플랫폼 제약 (솔직하게)

### 6-1. 설치 방식

| 기기 | 설치 방법 | 비고 |
|---|---|---|
| **아이폰** | **Safari**에서 열기 → 공유 → "홈 화면에 추가" | **Chrome(iOS)에서는 홈 화면 추가가 안 됨.** 반드시 Safari 안내 필요 |
| **안드로이드** | Chrome → "앱 설치" 배너 또는 메뉴 → 설치 | 대체로 자연스럽게 설치됨 |

- 첫 방문 시 기기를 감지해 **설치 안내 배너**를 띄웁니다 (iOS는 단계별 그림 안내).
- 설치 후에는 주소창 없이 **전체 화면**으로 실행 (`display: standalone`), 노치 영역 여백 처리.

### 6-2. 업데이트 방식

- Service Worker가 새 버전을 감지하면 **"새 모험 소식이 도착했어요 ✨"** 토스트 표시 → 누르면 새로고침.
- 깃허브에 푸시하면 다음 접속 때 자동 반영 (캐시 정책은 M0에서 확정).

### 6-3. 알려둘 제약 (미리 알고 가야 할 것)

| 항목 | 내용 | 대응 |
|---|---|---|
| iOS 푸시 알림 | 홈 화면에 설치된 경우에만 웹 푸시 가능 (iOS 16.4 이상) | "습격 시작" 알림은 **best-effort**로 설계, 핵심 기능으로 의존하지 않음 |
| iOS 오디오 | 첫 터치 후에만 재생 | 첫 화면 "시작하기" 버튼에서 오디오 잠금 해제 |
| 저사양 폰 | 4인 + 3D 실시간은 부하가 큼 | 그림자·풀 밀도 자동 낮춤 옵션, 프레임 측정 후 자동 조절 |
| 무료 백엔드 | Supabase 무료 프로젝트는 장기간 미사용 시 일시정지될 수 있음 | 가족·친구 플레이가 주기적으로 있으면 문제 적음. 정확한 정책은 가입 시 확인 |
| 동시 접속 수 | 실시간 연결 수에는 플랜별 상한 있음 | 소규모(방 수십 개)는 무료 범위 내로 예상, 실제 한도는 확인 필요 |

## 7. 감성 UI 가이드
